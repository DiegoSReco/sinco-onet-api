# Issue: score - agregacion entre corridas y parametros provisionales (2026-10-19)

`src/score/exposicion.py` implementa 001 sec. 4.4-4.5. Lo siguiente no esta fijado por ninguna decision; se implemento una opcion provisional (en `src/score/config.toml`) y requiere decision humana (regla 7). Hasta entonces, las salidas se rotulan "PROVISIONAL, SIN VALIDAR" (o "PILOTO, NO RESULTADO").

1. **Agregacion entre corridas.** 001 y 008 no dicen como combinar corridas (008: solo medir acuerdo). Opcion provisional: por ocupacion, media, minimo y maximo de cada medida entre corridas (`entre_corridas.metodo = media_min_max`); cada corrida se agrega primero por separado a O*NET y a SINCO. Alternativas: mediana, voto mayoritario por tarea antes de agregar, o promediar e_t por tarea. Esto cambia E_o cuando hay desacuerdo.
2. **Ponderacion por importancia/relevancia.** 001 4.4 lo deja [NO VERIFICADO]. Provisional: se calculan ambas, peso = `data_value` de las escalas IM (importancia) y RT (relevancia) de `tareas_onet_ratings`, sin transformar, solo sobre tareas core con peso disponible; se excluye `recommend_suppress = Y`. No se eligio una como principal. La frecuencia (FT) es categorica y no se usa. Las 418 tareas sin tipo no tienen ratings.
3. **Tareas sin tipo core/supplemental** (418; ver issue anotacion-core-vs-supplemental). 001 4.4 usa solo core: la medida principal las excluye; la variante `E_o_todas` las incluye junto con las suplementarias. Se reporta `n_sin_tipo`.
4. **Umbrales de cobertura.** `cobertura.umbral_tareas_onet = 0.5` (una O*NET es elegible si >= 50 % de sus tareas del universo estan anotadas) y `cobertura.umbral_onet_sinco = 0.5` (E_SINCO solo si >= 50 % de las O*NET emparejadas son elegibles; si no, NA con `cobertura_insuficiente`). Valores sin respaldo; con anotacion completa la cobertura sera 1. La cobertura de tareas usa como universo todas las tareas de `tareas_onet_en.parquet` (no distingue core).
5. **Pesos del crosswalk.** 001 4.5: pesos de crosswalk si existen, si no uniformes. El crosswalk (`sin_validar`) tiene `similitud` y `margen` pero no pesos; se usan pesos uniformes entre O*NET emparejadas. Ponderar por similitud (como en 005 para Frey-Osborne) o por empleo de EE. UU. (001 P6, fuente de empleo sin decidir) queda como sensibilidad futura.
6. **`crosswalk_confidence`.** El crosswalk no trae esa columna (docs: "no se llena"). Provisional: se reporta el peor `match_status` del grupo (ok < baja_confianza < sin_coincidencia). Los pares `sin_coincidencia` no cuentan como emparejados (005 5.6).
7. **`crosswalk_type`.** Los `tipo_relacion` son por par; si un grupo mezcla tipos se reportan unidos por `;`.
8. **Criterio de "piloto".** Umbrales 0.95 de cobertura de ocupaciones/tareas y prefijos de run_id (`[piloto]`) son provisionales; sirven solo para que el CLI se niegue a producir cifras sobre anotacion parcial.
9. **Definicion de `share_E2` / `share_any`.** Se calculan sobre tareas core (mismo conjunto que la medida principal); 001 no especifica el conjunto.
